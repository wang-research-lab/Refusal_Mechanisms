# Component and Dimension Sparsity in Transformer Refusal Mechanisms

Code and results for our COLM 2026 paper on characterizing sparse refusal mechanisms in transformer language models. We identify which attention and MLP components can be used to replicate refusal steering across four open-weight models, and which residual stream dimensions within those components carry the signal.

## Results layout

All raw results are included in [`pipeline/runs/`](pipeline/runs/), organized by model. Each model directory contains:

- `completions/component_test/` — main results: component mechanism evaluations, complement evaluations, and dimension sparsity results at the identified anchor layer
- `completions/full_sweep/` — exhaustive layer sweep results (last post-instruction token) used to select the anchor layer
- `completions/norm_sweep/` — dimension sparsity sweep across retention levels (50–97.5%) on the top-ASR layers
- `completions/pruning/` — Stage 2 greedy elimination logs (one file per pruning step; large)
- `completions/rotation_control/` — random orthogonal rotation control results at the top-ASR layer, used to validate that coordinate sparsity reflects genuine basis alignment rather than an artifact of masking
- `exhaustive_set_anchor_<L>_determinstic.json` — the identified mechanism
- `pile_loss.json` — CE loss and perplexity for the base, full-steering, and mechanism conditions

Cross-model summaries live at the top level of `pipeline/runs/`:

- `rebuttal_threshold_seed_results.json` / `.md` — α/τ threshold sweep and seed-stability results (paper Appendices A.11–A.12)
- `rotation_control_summary.json` — rotation control aggregated across models (Appendix A.7)
- `position_perturbation_table.md` — per-component attribution stability across read-out positions
- `pipeline/parsed_logs/` — MMLU and GSM8k scores per model and condition, with `_summary.md` as the headline table (Appendix A.13)

Figures and summaries can be regenerated from saved results using the plotting scripts provided.

**Not included:** the per-removal completion traces generated by the threshold and seed sweeps (~4.3 GB, one file per candidate removal per configuration). The endpoint evaluations that back every number in the paper are included; the intermediate traces can be regenerated with the commands below, or requested from the authors.

## Main results

### `pipeline/sweep_layers.py`

Sweeps steering across all layers to identify the effective steering window, and optionally runs the norm sweep and rotation control.

```bash
python -u -m pipeline.sweep_layers --model_path microsoft/Phi-4-mini-instruct --run_norm_sweep --batch_size 128 --use_existing
```

Key arguments:
- `--run_norm_sweep`: Runs dimensional sparsity testing (using 50, 70, 80, 90, 95, 97.5% of dimensions) on the top performing layers by ASR
- `--run_rotation_control`: Runs random orthogonal rotation control on the top-ASR layer at the same dimension budgets as the norm sweep, validating that coordinate alignment drives performance rather than dimensionality alone
- `--num_rotation_trials`: Number of independent rotation trials per threshold (default: 5)
- `--use_existing`: Skip recomputation and load saved artifacts where available

### `pipeline/steer_components.py`

Runs the full mechanism analysis: refusal direction extraction, two-stage greedy component elimination, complement validation, and dimension sparsity analysis.

```bash
python -u -m pipeline.steer_components --model_path mistralai/Mistral-Small-3.2-24B-Instruct-2506 --anchor_layer 17 --heuristic_threshold 0.95 --sparse_threshold 0.95 --batch_size 128 --use_existing
```

Key arguments:
- `--anchor_layer`: Layer at which the refusal direction is extracted. We use the top performing layer from `sweep_layers.py`
- `--heuristic_threshold`: Stage 1 pruning threshold, α in the paper (projection-based pre-filter)
- `--sparse_threshold`: Threshold for dimension sparsity analysis
- `--use_existing`: Skip recomputation and load saved artifacts where available

The per-model anchor layers are Gemma-2-2B-IT 13, Phi-4-mini-instruct 14, Mistral-Small-3.2-24B 17, and Qwen3-4B 19.

## Appendix results

### Threshold sensitivity and seed stability

`pipeline/threshold_seed_sweep.py` reruns mechanism identification across the α/τ grid and under random tie-breaking. Experiment 1 sweeps τ ∈ {0.02, 0.05, 0.10} at α = 0.95, experiment 2 sweeps α ∈ {0.90, 0.95, 0.99} at τ = 0.05, and experiment 3 reruns Stage 2 with random tie-breaking (ε = 0.005) under three seeds.

```bash
# One model at a time; each writes a per-model sidecar so models can run in parallel
python -m pipeline.threshold_seed_sweep --model_path google/gemma-2-2b-it --anchor_layer 13 --experiment all

# Aggregate all sidecars into the combined report and tables
python -m pipeline.threshold_seed_sweep --report
```

`pipeline/tie_density.py` reports how often Stage 2 candidates tie within ε on the deterministic trajectory, which is what makes the seed experiment meaningful.

### Capability retention

`pipeline/save_ortho_weights.py` bakes an intervention into a model's weights and writes a standard HF checkpoint, so it can be served with vLLM (which cannot run the Python activation hooks used elsewhere in this repo). The `full` setting projects the direction out of every residual-writing weight below the anchor layer; the `mechanism` setting restricts to the identified components and the norm-explained coordinate mask.

```bash
python -m pipeline.save_ortho_weights --model_path google/gemma-2-2b-it --setting full
python -m pipeline.save_ortho_weights --model_path google/gemma-2-2b-it --setting mechanism --sparse_threshold 0.95
```

Checkpoints are written under `$HF_HUB_CACHE`. `serve_and_eval.sh` then serves a checkpoint under vLLM and runs the `inspect_evals` MMLU and GSM8k tasks against it; set `MODEL_HUB_ROOT` to the directory holding the baked checkpoints if it differs from `$HF_HUB_CACHE`. `pipeline/parse_eval_logs.py` collects the resulting eval logs into `pipeline/parsed_logs/`.

Perplexity does not require serving, and evaluates all three conditions in a single pass over one loaded model:

```bash
python -m pipeline.eval_pile --model_path google/gemma-2-2b-it --n_batches 64
```

### Position perturbation

`pipeline/position_perturbation.py` recomputes each mechanism component's linear attribution to the refusal direction at several post-instruction token positions, holding the direction fixed. This is a descriptive characterization, not a hypothesis test; it reports Spearman correlation, mean |α|, and magnitude shift only.
